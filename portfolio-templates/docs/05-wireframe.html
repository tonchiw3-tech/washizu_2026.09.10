1 ワイヤーフレーム作成方法

Figmaを使用して、旅香 - TABIKA - のWebサイトおよびWebアプリケーションのワイヤーフレームを作成する。

本サイトでは、香水づくりを最初から目的として検索している人だけではなく、

  • 浅草観光を楽しみたい
  • ものづくりを体験したい
  • 2〜3時間程度の時間がある
  • 一人でゆっくり過ごしたい
  • イベント前後に時間がある
  • 雨の日に室内で楽しめる場所を探している

といった利用者が、自分の状況からinimuの香りづくり体験を発見し、予約まで進めることを目的とする。

そのため、ワイヤーフレームでは、

「利用者の状況から探す → おすすめの過ごし方を知る → 香りづくり体験を知る → 空き状況を見る → 予約へ進む」

という流れを重視して設計する。

配置意図の説明

① ヘッダー

ページ上部にロゴ「旅香 - TABIKA -」と、

  • 香りづくり体験
  • おすすめの過ごし方
  • アクセス・周辺情報
  • FAQ
  • 予約

へのナビゲーションを配置する。

どのページを閲覧していても、体験内容や予約ページへ移動できるようにするためである。

特に「空き状況を見る」「予約する」などのCTAを目立つ位置に設け、興味を持った利用者が迷わず予約行動へ進めるようにする。

② ヒーローセクション

トップページの最初に、

「浅草で、自分だけの日本の香りをつくる旅。」

というコンセプトと、浅草・香りづくりをイメージできる写真を配置する。

最初にサービスの世界観を伝えることで、「香水を買うサイト」ではなく、浅草で体験するサービスであることを理解してもらう。

CTAとして、

「自分に合った過ごし方を探す」

または

「空き状況を見る」

を配置する。

③ 利用シーンから探す

ヒーローセクションの直後に、

  • 浅草観光
  • ものづくり
  • すき間時間
  • 一人時間
  • イベント前後
  • 雨の日

の6つの利用シーンをカード形式で配置する。

利用者が「香水を作りたい」と考えていなくても、現在の予定や状況から自分に合ったページへ進めるようにするためである。

④ 香りづくり体験の紹介

利用シーンの次に、inimuで行われている香りづくり体験を紹介する。

主な掲載内容は、

  • 26種から香りを選べる
  • 自分だけの香りをつくれる
  • 完成した香りを持ち帰れる
  • 浅草でものづくりを体験できる

などとする。

利用シーンから興味を持った利用者に、「実際に何ができるのか」を伝える役割を持たせる。

⑤ 体験の流れ

香りづくりの流れを、

選ぶ → 試す → 組み合わせる → 完成 → 持ち帰る

のように段階的に表示する。

初めて参加する利用者でも、体験内容を具体的に想像できるようにし、予約前の不安を減らす。

⑥ おすすめの過ごし方

香りづくり体験だけを単独で紹介するのではなく、

浅草寺 → ランチ → 香りづくり → カフェ

などのモデルコースを紹介する。

香りづくりを浅草観光の1日の中に組み込んで見せることで、「ワークショップに参加する」という目的がなかった利用者にも選択肢として認識してもらう。

⑦ 浅草とものづくり

浅草を含む台東地域が、古くからものづくり文化を持つ地域であることを簡潔に紹介する。

inimuの香りづくりを単なる香水づくりではなく、

「ものづくりのまち・浅草で、自分だけの香りをつくる体験」

として位置づける。

⑧ アクセス

inimuの所在地、最寄駅、Googleマップを配置する。

予約を検討している利用者が、

「どこにあるのか」

「浅草観光から行きやすいのか」

をすぐ確認できるようにする。

また、会場が2階にあることなど、来店前に必要となる情報も分かりやすく掲載する。

⑨ 最後のCTA

ページの最後に、

「浅草で、自分だけの香りをつくってみませんか？」

などのメッセージと、

「空き状況を見る」

ボタンを配置する。

ページを最後まで閲覧して体験への理解が深まったタイミングで、予約行動につなげる。

⑩ フッター

フッターには、

  • 旅香 - TABIKA -
  • 香りづくり体験
  • おすすめの過ごし方
  • アクセス
  • FAQ
  • 予約
  • inimu公式サイト

などのリンクを配置する。

ページ最下部からも必要な情報に移動できるようにする。

4 Webアプリケーション画面

本制作では、管理画面ではなく、利用者が条件を選択しておすすめの過ごし方を探すWebアプリケーションを制作する。

そのため、テンプレートに記載されている「ログイン・一覧・登録・編集」ではなく、本企画に必要な画面をワイヤーフレームとして作成する。

① 条件選択画面

利用者が、

利用シーン

  • 浅草観光
  • ものづくり
  • 空き時間
  • 一人時間
  • イベント前後
  • 雨の日

利用できる時間

  • 2時間
  • 3時間
  • 半日

出発地点

  • 浅草
  • 上野
  • 東京ドーム
  • 両国
  • 日本武道館
  • 東京国際フォーラム

天候

  • 晴れ
  • 雨

などの条件を選択できるようにする。

画面下部に、

「おすすめを見る」

ボタンを配置する。

② おすすめプラン一覧画面

選択した条件に合わせて、

  • モデルコース名
  • 所要時間
  • 香りづくり体験
  • 移動時間
  • おすすめポイント

をカード形式で表示する。

利用者が複数の候補を比較し、自分に合ったプランを選べるようにする。

③ おすすめプラン詳細画面

選択したモデルコースについて、

  • タイムスケジュール
  • 移動
  • 観光スポット
  • 香りづくり体験
  • 所要時間
  • アクセス

を詳しく表示する。

最後に、

「空き状況を見る」

CTAを配置し、既存予約ページへつなげる。

Webアプリケーションの基本フロー

トップページ → 利用シーンを選ぶ → 時間・出発地点・天候を選ぶ → おすすめプラン一覧 → プラン詳細 → 香りづくり体験を確認 → 空き状況を見る → 既存予約ページ

という流れとする。

配置意図

観光中の利用者がスマートフォンから検索することを想定し、PC版よりも操作を単純化する。

主なポイントは、

  • ヘッダーをコンパクトにする
  • メニューはハンバーガーメニューを使用する
  • 利用シーンカードを縦方向に配置する
  • CTAボタンをタップしやすい大きさにする
  • 文章を短くする
  • 写真を大きく表示する
  • 「空き状況を見る」ボタンを分かりやすく配置する

ことである。

特に、観光中・移動中・雨天時などにスマートフォンから短時間で情報を確認し、予約ページへ進める操作性を重視する。
