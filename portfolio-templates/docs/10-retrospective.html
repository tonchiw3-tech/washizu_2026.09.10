1 プロジェクト振り返り

企画・設計段階の振り返り 必須

当初は「旅香 - TABIKA -」として、観光やイベントの前後に生まれる空き時間を活用し、香りづくり体験を提案するサービスを企画しました。市場調査、競合分析、SWOT分析、4C分析、ペルソナ設計を行い、利用者が体験を知り、予約まで進む導線を整理しました。

制作中に外部サービスとの連携や実装期間に課題があることが分かり、実現可能性を見直しました。その結果、サービスの核を「香りをつくる体験」へ整理し、現在の「香作（こうさく）」に計画を変更しました。企画の魅力だけでなく、実装可能性と制作期間を早期に確認する重要性を学びました。

デザイン段階の振り返り 必須

Figmaでサイトマップ、ワイヤーフレーム、画面構成を作成しました。利用者が最初に必要とする情報を考え、体験内容から予約まで迷わず進める導線を意識しました。実際のブラウザ表示で画像、文字、アイコン、住所表示を確認しながら修正し、UI/UXは見た目だけでなく情報の伝わりやすさと操作性が重要だと学びました。

フロントエンド実装の振り返り 必須

HTMLで構造を作り、CSSでレイアウトや配色を調整し、JavaScriptで画面操作を実装しました。画像やファイルの参照先、PCとスマートフォンの表示差、修正内容が公開ページに反映されない問題に苦労しました。VS Code、Codex、GitHub、SourceTreeを組み合わせ、動作確認、修正、バージョン管理までが開発工程であることを学びました。

バックエンド実装の振り返り 必須

職業訓練ではJava・Spring Boot・MySQLを学びました。一方、今回の卒業制作では静的なWebサイト制作を優先したため、Java・Spring Boot・MySQLによるバックエンド機能や外部サービス連携は実装していません。実装した内容と、今後実装したい内容を区別して考える重要性を学びました。

全体を通しての学び 必須

32日間の制作で、課題を整理し、必要な機能を考え、画面として形にする力が成長しました。AIの回答と実際のファイル変更が一致するとは限らないため、ソースコード、ブラウザ表示、Gitの変更履歴を確認し、修正と検証を繰り返すことが開発だと学びました。

2 技術記事

技術記事タイトル

GitHub PagesでWebサイトが正しく表示されない原因と解決方法――ファイル配置と相対パスを学ぶ

はじめに

卒業制作ではHTML・CSS・JavaScriptでWebサイトを制作し、GitHub Pagesで公開しました。ローカルでは表示できても、公開先でトップページが表示されなかったり、修正内容が反映されなかったりする問題がありました。

原因と修正

GitHub Pagesでは、公開元に設定したフォルダと、そこにあるindex.htmlの配置が重要です。公開元がリポジトリのルートであれば、トップページのindex.htmlもルートに配置します。CSS・JavaScript・画像はHTMLから見た相対パスにします。例：./css/style.css、./js/main.js、./assets/main.jpg。

結果と学び

サイト一式をサブフォルダからリポジトリ直下へ移動し、関連ファイルの階層をそろえました。ローカルでの確認、GitHubへの反映、公開サイトでの確認はそれぞれ異なる状態です。AIに修正を依頼した場合も、実際のファイル、ブラウザ表示、Gitの変更履歴を確認することが重要だと学びました。
