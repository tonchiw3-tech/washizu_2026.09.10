1 プロジェクト振り返り

企画・設計段階の振り返り 必須
マーケットリサーチ、ペルソナ設計、情報設計について

マーケットリサーチでは、最初は「ワークショップの予約数を増やす」という課題に対して、施策の方向性が広がりすぎてしまい、企画の軸を決めることに苦労しました。競合分析や自社データを整理する中で、ワークショップ自体には既に実績があり、課題は体験そのものよりも、ユーザーがどのように体験を知り予約へ進むかというWeb導線にあると考えました。ペルソナや利用シーンを整理したことで、「浅草観光」「空き時間」「一人時間」「雨天」などから体験へつなげる情報設計ができました。次回は、事実・仮説・施策を早い段階で分け、企画の軸をより早く定めたいです。

デザイン段階の振り返り 必須
デザインガイドライン、ワイヤーフレーム、Figma作業について

デザイン段階では、ワイヤーフレームを作成する中で、見た目だけでなく、利用者がどの順番で情報を知りたいかを考えて配置することを意識しました。特に、体験内容、利用シーン、アクセス、FAQ、予約CTAまでの流れを整理し、迷わず予約へ進める画面構成を目指しました。一方で、Figmaではフレーム、余白、文字サイズ、画像配置などの調整に時間がかかりました。また、デザイン画像では良く見えても、実際のWeb画面では印象が変わることも学びました。今後はAuto Layoutやコンポーネントを活用し、修正しやすく、実装しやすいデザインデータを作れるようになりたいです。

フロントエンド実装の振り返り 必須
HTML/CSS/JavaScript の実装について

HTML/CSS/JavaScriptの実装では、Figmaで作成したデザインをWeb上で再現することの難しさを感じました。特に、文字の重なり、画像やアイコンの大きさ、余白、住所の折り返しなど、細かな部分を一つずつ確認しながら修正しました。また、AIへ修正を依頼するときも、「見た目がおかしい」という曖昧な指示ではなく、「どの要素を、どのように変えたいか」を具体的に伝える必要があると学びました。今後はHTMLの構造とCSSの役割をより理解し、AIが作成したコードでも、自分で問題箇所を見つけて修正できる力を身につけたいです。

バックエンド実装の振り返り 必須
Java/Spring Boot の実装について

今回の「旅香 - TABIKA -」では、フロントエンド制作を優先したため、Java/Spring Bootを使ったバックエンド実装までは行いませんでした。ただし、企画段階では、利用シーン、空き時間、出発地点などの条件からおすすめプランを表示するWebアプリ機能を想定しました。これまでの学習では、Spring Boot、MyBatis、MySQLを使用したTodoアプリを制作し、画面からデータベースまで処理がつながる仕組みを経験しています。今後は、その知識を活かして旅香にもバックエンドを追加し、条件検索とデータベースを連携させたいです。今回、実装範囲を絞る重要性と、次の開発段階を見据えて設計することの大切さを学びました。

全体を通しての学び 必須
32日間のプロジェクト全体を通して学んだこと

32日間のプロジェクトを通して最も成長したのは、制作を始める前に「誰の、どのような課題を、どのような方法で解決するか」を考える力です。一番苦労したのは、マーケットリサーチ、ペルソナ、サイト構造、Figma、フロントエンド実装までを一貫した考え方でつなげることでした。プロンプトプログラミングでは、AIに任せれば完成するのではなく、指示する側が目的や修正箇所を具体的に理解していることが重要だと感じました。特にHTML/CSS、Spring Boot、Git/GitHubのチュートリアルで学んだ内容が、実際の制作を通してつながりました。今後はAIの出力をそのまま使うのではなく、自分で内容を確認・判断・修正できる力を伸ばし、利用者と現場双方にとって使いやすいサービスを作れるようになりたいです。

2 技術記事

技術記事タイトル 必須

Git/GitHubでWeb制作物をコミット・プッシュするまで ― 初学者がつまずいたポイントと解決方法

記事本文 必須
上記の構成に沿って記事本文を記載。コードブロックを含めてください。

1. はじめに

卒業制作では、HTML/CSS/JavaScriptで制作したWebサイトをGitHubへ登録し、提出する必要がありました。授業の中でGitやGitHubについて学習した経験はありましたが、実際に自分の制作物を更新しながら操作すると、思っていた以上に分からないことが多くありました。

特に困ったのは、変更したファイルがソース管理に表示されない、コミットしたつもりでもGitHubに反映されない、どのリポジトリに接続されているのか分からない、VS CodeとGitHubの関係が分からなくなる、といった問題です。

2. 課題

最初に分かりにくかったのは、「保存」「コミット」「プッシュ」の違いでした。VS Codeでファイルを保存するとパソコン上のファイルは更新されますが、その時点ではGitHubには何も送られていません。Gitでは、変更、ステージング、コミット、プッシュの順で作業します。

3. 調査

問題が起きたときは、VS Codeの画面だけで判断せず、ターミナルでGitの状態を確認しました。

# 現在のGitの状態を確認する
git status

# GitHubの接続先を確認する
git remote -v

# 現在のブランチを確認する
git branch

git statusでは変更されたファイルを、git remote -vでは接続先を、git branchでは現在のブランチを確認できます。

4. 実装

# 1. 現在の変更内容を確認
git status

# 2. 変更したファイルをステージング
git add .

# 3. 変更内容をコミット
git commit -m "Webサイトのデザインを修正"

# 4. GitHubへ送信
git push

git add .は変更を次のコミットに含める操作、git commitはローカルへ記録する操作、git pushはGitHubへ送信する操作です。保存しただけではGitHubには送られません。

5. 結果

「修正する → 状態を確認する → ステージングする → コミットする → プッシュする → GitHubで確認する」という流れを意識することで、作業のどの段階にいるのかが分かりやすくなりました。GitHubは単なる提出先ではなく、制作物の変更履歴を保存できる場所だと理解できました。

6. 学び

エラーやトラブルが発生したときは、すぐに操作を繰り返すのではなく、現在の状態を確認することが重要だと学びました。AIに質問するときも、どの画面で止まっているか、どの操作まで行ったか、git statusの表示、エラーメッセージを伝えた方が、より正確な回答を得られます。今後はブランチ、マージ、コンフリクトなども練習したいです。

4 今後の学習計画

今後学びたい技術・分野 必須
今後のキャリアに向けて学習したい技術やスキル

今後は、フロントエンド、Java/Spring Boot、データベース、UI/UX、AI活用を一つのWebサービスとして組み合わせて開発できる力を身につけたいです。特に「旅香 - TABIKA -」を発展させ、バックエンドまで含むWebアプリとして完成させます。

短期：1か月以内

Java／Spring Bootで、利用シーン、空き時間、出発地点に応じておすすめプランを表示する仕組みを作ります。MySQLへの登録、データ取得、条件検索、画面表示、フロントエンド連携を目指します。

中期：半年〜1年

ログイン・認証、データベース設計、REST API、バリデーション、例外処理、外部API連携、テスト、セキュリティを学習します。利用者の使いやすさと業務課題の解決も意識して設計できるようになりたいです。
